We want to redesign the voice input system of the Android app "Šturmanas Bajeristas" into a modern always-listening architecture suitable for driving.

Current state:

- Google Navigation SDK is working.
- Navigation guidance works.
- AI conversation works.
- TTS works.
- Navigation ↔ AI pause/resume logic already works.
- ConversationEngine already processes final transcript text correctly.
- The current SpeechRecognizer implementation is unreliable on Xiaomi devices:
  - many ERROR_NO_MATCH (code 7)
  - repeated startListening() sessions
  - audible system beeps
  - user often has to repeat commands

The goal is NOT to improve SpeechRecognizer.

The goal is to replace it with a modern continuous microphone pipeline.

Target architecture:

AudioRecord
→ continuous PCM audio
→ lightweight local Voice Activity Detection (VAD)
→ detect speech start
→ detect speech end
→ create utterance buffer
→ send only the utterance to Speech-to-Text
→ inject the final transcript into the existing ConversationEngine

Requirements:

- continuous listening
- no Android recognition beeps
- minimal latency
- excellent Lithuanian recognition
- suitable while driving
- microphone pauses automatically while our own TTS or navigation is speaking
- microphone resumes automatically afterwards
- assistant must never recognize its own TTS
- preserve all existing ConversationEngine logic
- preserve navigation queue logic
- preserve AI state machine
- preserve semantic completion logic
- preserve navigation guidance
- do not perform unnecessary refactoring
