Proceed with Phase 3 integration now.

Decision:

Remove the old Android SpeechRecognizer implementation completely.

Do not keep a feature flag.
Do not keep dual voice-input systems.
Do not preserve fallback code for SpeechRecognizer.
The old implementation is unreliable and will not be used again.

GOAL

Integrate the new microphone pipeline directly into the production voice flow:

AudioRecord
→ Silero VAD
→ TranscriptionClient
→ OpenAI transcription
→ AIConversationController
→ existing transcript processing
→ KentasChat
→ existing AI TTS

REQUIRED ACTIONS

1. Fully remove SpeechRecognizer

Delete all code related to:

- android.speech.SpeechRecognizer
- RecognitionListener

- recognizerIntent

- stopSttSession()

- all SpeechRecognizer restart runnables and tokens

Remove unused imports, fields, handlers, constants, and diagnostic logs.

2. Integrate ContinuousMicrophonePipeline

The production controller must use the new pipeline as the only microphone input source.

Flow:

ContinuousMicrophonePipeline
→ final transcript
→ AIConversationController.onTranscriptReceived(text)
→ existing processPacket(text, isFinal = true)

Do not bypass the existing transcript processing logic.

Preserve:

- utterance buffering
- duplicate text handling
- semantic completion
- wake-word handling
- ConversationMode
- Phase state machine
- KentasChat
- AI response handling
- AI TTS
- navigation pause/resume behaviour

3. Pipeline lifecycle

Create and own the production microphone pipeline in the most appropriate lifecycle owner.

Requirements:

- start when voice listening should become active
- stop and release on controller/ViewModel destruction
- never leak Activity or Context
- never run multiple AudioRecord instances
- repeated start calls must be safe
- repeated stop calls must be safe

4. Replace old state side effects

Where the old state machine called:

- startSttSession()
- stopSttSession()

replace those effects with the new pipeline controls.

Expected behaviour:

LISTENING / COLLECTING / IDLE when listening is allowed:
- pipeline.unmute()
- pipeline.start() if not already running

THINKING:
- pipeline.mute()
- discard active utterance buffer

SPEAKING:
- pipeline.mute()
- discard active utterance buffer

PAUSED_BY_NAVIGATION:
- pipeline.mute()
- discard active utterance buffer

MUTED:
- pipeline.mute()

Do not repeatedly stop and recreate AudioRecord during normal phase transitions.

AudioRecord should remain alive while the voice system is enabled.
Use mute/unmute as the normal control mechanism.

5. Prevent self-recognition

Before AI TTS begins:

- mute pipeline
- clear pre-roll
- clear current utterance
- reset VAD/segmenter state

After AI TTS finishes:

- wait a short configurable cooldown
- reset segmenter state again
- unmute pipeline
- resume listening

Apply equivalent behaviour for navigation TTS through the existing ConversationCoordinator callbacks.

The microphone must never transcribe:

- Kentas AI speech
- navigation instructions
- residual speaker echo immediately after TTS ends

6. Navigation integration

Keep NavigationVoiceController and ConversationCoordinator architecture intact.

Existing callbacks:

onNavigationStarted(id)
onNavigationFinished(id)

must now control pipeline mute/unmute rather than SpeechRecognizer cancellation/restart.

Preserve activeNavUtterances tracking.

Only unmute after:

- all navigation utterances have completed
- AI TTS is not active
- controller is not in MUTED mode
- cooldown has elapsed

10. Error handling

Production behaviour must survive:

- AudioRecord initialisation failure
- microphone permission failure
- ONNX model loading failure
- transcription timeout
- network loss
- HTTP errors
- empty transcript
- transcription queue full

- log the reason
- return to listening
- do not crash
- do not permanently mute the microphone
